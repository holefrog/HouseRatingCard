每天一次，同步 VPS 评分卡（唯一数据源）与 MLS 挂牌信息，并备份数据。不要改动 Muse 项目评分卡，它已中止，不再是数据源。（2026-11-13 评分卡已迁至新 VPS muse-free-vm，本任务目标随迁；旧机 <旧机IP> 上的卡已停用，不得再写。）

VPS：IP <VPS_IP>，SSH 用户 <SSH_USER>，端口 22122，部署私钥在 Muse 侧 ~/.ssh/<部署私钥>，known_hosts 用 ~/.ssh/known_hosts_vps（只用该钥匙 SSH，绝不要在聊天、文件或 cron 记录里写任何密码；web 登录密码与 SSH 无关，本任务不走 web 登录接口）。
数据文件：VPS /home/<SSH_USER>/rating-card-vps/houses.json。范围以该文件当次实际内容为准，覆盖全部条目，不再限定固定套数或 id 段（2026-10-28 早晨卡上为 64 套，id 1-64；此后卡扩容时以文件为准，勿因旧数字漏同步新房）。MLS 号见该文件。
决策状态有五种：保留、排除、售出/下架/过期、新增、新盘。售出/下架/过期是挂牌已不在市的合一状态，包括 Pending（待成交）——即 Sold / Terminated / Expired / Pending 都归入这一状态，不强制 rating=1，不清评分和备注，不计入小区颜色。新增是新抓取未筛选的房子，未评分，不能直接打分。新盘是开发商新盘/预售，未评分、已有评分冻结，不能直接打分。

请求频率（2026-10-29 用户指示，不着急、避免 429 为优先）：
- 逐套串行核实，绝不并行、绝不批量突发请求；每套之间主动停顿放慢节奏，宁可整轮跑久一点，也不要快。
- 同一来源连续请求更要拉开间隔；不要在短时间内对同一站点密集抓取。
- 一旦遇到 429 / 限流：立即停止对该来源的后续请求，不要重试、不要换着法子绕过去继续抓；该来源剩余的套一律留原值、记为未核实，汇报时说明是因限流停下，明天再继续。
- 完成度让位于不触发限流：未核实可以接受，触发 429 不可以接受。

步骤：
1. SSH 上 VPS，先备份：cp houses.json houses.json.bak-<日期>，再把 houses.json 拷回 Muse 侧 ~/workspace/rating-card-vps/houses-backup-<日期>.json（只备份，不回写、不覆盖 web 数据）。每次运行都以 VPS 上当次的 houses.json 为准，不要用旧本地副本覆盖或限定范围。
2. 逐套用 MLS 号 + 地址在网上核实挂牌信息（优先 Realtor.ca，其次可信第三方镜像；没有官方 MLS API，核实不到就留原值、记为未核实，绝不编造价格、状态或链接，绝不用邻户页面顶替）。核实时执行上面的请求频率规则。
3. 更新规则：
   - 价格、面积、房数、车位（parking，挂牌页的 Parking Spaces 与 Parking Details，记为“<个数> · <明细>”，如“2 · Underground”，明细照挂牌原文；核实不到就留原值，不猜）、物业费（strataFee，即挂牌上的月物业费，如 REW 页面的 Strata Maintenance Fees；挂牌明确无物业费、或核实到的挂牌页根本没有该费用项时为 0；核实不到物业费时留原值，不猜）、挂牌链接：核实到变化就更新。例外：id182（3 1615 Shaughnessy）的面积按户型图宜居 3,125 尺（MLS 4,561 尺为建筑总面积），同步不得改回 4,561（2026-11-11 用户定案）。房数里的卫数（baths）只是照挂牌页原样记录的数，不参与任何筛选/排除判断，不要为它单独定口径或在汇报里特别提出（2026-11-03 用户明示：他从没要求过考虑卫生间数目）。
   - 建筑商（builder）：按你核查，是哪家就写哪家（2026-11-11 用户定案，放宽旧口径）——本次核实能确立开发商/建筑商公司名时就补上（照原文，如 Bosa Properties）；页面没明写就继续留空，绝不拿小区名顶替、绝不猜。
   - 查到 Sold / Terminated / Expired / Pending（售出/下架/过期，含 Pending）：自动把该套的 status 改成“售出/下架/过期”，一律压过原状态——当时是“保留”、“排除”或“新盘”的房子都自动改，不再有“已排除保持排除”的例外；新盘自动转是 2026-11-10 用户定案（id266 为首例）。当时是“新增”的房子也不自动改状态，只在汇报里列出，由用户决定。改状态时在备注（note）末尾追加价格记录（2026-11-10 用户定案）：Sold/Pending 的追加“已售出：挂牌 $<卡上挂牌价>，成交 $<本次核实到的成交价>”；成交价核实不到时追加“已售出：挂牌 $<挂牌价>，成交价未核实”，绝不编造成交价；Terminated/Expired 没有成交的，追加“已下架/过期：挂牌 $<挂牌价>”。备注原有内容一律保留、不删改；备注已有同类价格记录的不重复追加。除备注按此追加外，绝不改 rating、viewed、exclusionReason、poorEnv。
   - 其他决策字段一律不动。
   改动前先校验 JSON 有效，改动后在 VPS 上用 python json 校验 houses.json 并用 systemctl status rating-card 确认服务仍在运行（不要用无登录 curl 调 /api/houses 验证，那会返回 401，那是密码登录在正常工作，不是故障）。
4. 汇报规则：无变化时不要打扰用户（在本次运行记录里写“无变化”即可）；有变化时，在本对话汇报变化清单（id、地址、MLS、旧值→新值、来源页），并说明哪些套未核实到；自动改成售出/下架/过期的要单独列出。照片不在本次同步范围内（照片是一次性迁移任务，另行处理）。

注意：如 SSH 不通、VPS IP 已变、或 houses.json 校验失败，停止写入，汇报失败原因，不要用旧数据覆盖，也不要重试覆盖写。
