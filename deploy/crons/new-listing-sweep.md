背景：用户 2026-10-30 批准设立本任务：“每天自动扫新房源，新房以新增入卡并汇报”。本任务排在每日 MLS 同步（约 9:13）之后运行，避免两个任务同时写 houses.json；开始前先确认同步任务没有正在写卡，如怀疑有冲突就等几分钟再开始。

VPS：IP <VPS_IP>，SSH 用户 <SSH_USER>，端口 22122，部署私钥在 Muse 侧 ~/.ssh/<部署私钥>，known_hosts 用 ~/.ssh/known_hosts_vps（只用该钥匙 SSH，绝不要在聊天、文件或 cron 记录里写任何密码；web 登录密码与 SSH 无关，本任务不走 web 登录接口）。
数据文件：VPS /home/<SSH_USER>/rating-card-vps/houses.json。范围以该文件当次实际内容为准。

过滤条件（用户定，2026-10-27/28 两次全市场扫描用的同一套；类型于 2026-11-04 经用户批准加入独栋）：
- 地区：Burnaby、Coquitlam、Port Coquitlam、Port Moody。
- 类型：双拼（duplex）、Townhouse 或独栋（detached / single-family house）。
- 价格：$800,000–$1,200,000 CAD。
- 状态：在售。
- 与卡上现有房子按 MLS 号 + 地址去重，已有的不重复加（地址归一化比对：门牌号与街道名对上即视为同一套；同一地址不同 unit 号是不同套）。

请求频率（2026-10-29 用户指示，不着急、避免 429 为优先）：
- 逐套串行核实，绝不并行、绝不批量突发请求；每套之间主动停顿放慢节奏，宁可整轮跑久一点，也不要快。
- 同一来源连续请求更要拉开间隔；不要在短时间内对同一站点密集抓取。
- 一旦遇到 429 / 限流：立即停止对该来源的后续请求，不要重试、不要换着法子绕过去继续抓；该来源没扫完的部分记为未核实，汇报时说明是因限流停下，明天再继续。
- 完成度让位于不触发限流：未核实可以接受，触发 429 不可以接受。

步骤：
1. SSH 上 VPS，先备份：cp houses.json houses.json.bak-<日期>，再把 houses.json 拷回 Muse 侧 ~/workspace/rating-card-vps/houses-backup-<日期>.json（只备份，不回写、不覆盖 web 数据）。每次运行都以 VPS 上当次的 houses.json 为准，不要用旧本地副本覆盖或限定范围。
2. 在 REW（优先）上按上面过滤条件扫描四城在售房源（可辅以 Realtor.ca / 可信第三方镜像交叉确认，但入卡核实标准是 REW 现挂牌：价格、面积、MLS 号对得上才算，绝不拿旧挂牌或邻户页面顶替）。把扫到的结果逐套与卡上现有 MLS/地址去重，只留下真新房。
3. 对每套真新房，按卡上手动加房同一套核实流程补齐字段：地址、城市、邮编、小区（community）、价格、面积、房数（beds/baths，照 REW 页原样记；卫数不参与入卡分类，分类只看卧室数 beds）、车位 parking（REW 页 Parking Spaces 与 Parking Details，记为“<个数> · <明细>”，如“2 · Underground”，明细照原文；页面没有车位信息就留空）、建筑商 builder（REW 页或其 Building Information 明确写出开发商/建筑商公司名才填，照原文；没明写就留空，绝不拿小区名顶替）、MLS、类型（双拼/Townhouse/独栋；独栋的 propertyType 记“独栋”）、建筑年代（REW 有就填、没有留空，不要猜）、物业费 strataFee（REW 页 Strata Maintenance Fees 行；无该行或文案明示无物业费填 0；独栋多为非 strata、无物业费行，按此填 0，个别 strata 独栋按页面实际行填）、挂牌链接、封面照片（下载 REW 封面图到卡的 photos 目录并按现有命名规则引用）、经纬度（坐标来源只认两个：REW 挂牌页自带坐标，或 BC Geocoder 按完整门牌地址匹配、score 高且精度为门牌级 CIVIC_NUMBER 的结果；落点必须再用邮编复核——点落在该邮编附近、同小区聚类一致；只有街名级匹配的点一律不用，2026-10-27 曾因用街名级点把 5350 Manor 钉错 2.6 公里；定不到门牌级可靠坐标就留空，不要乱填）。
4. 入卡分类（套用用户既有规则）：
   - 一般新房：status=“新增”，未评分（rating 空）、viewed=false。新增不能直接打分，须由用户先改保留或排除。
   - 自动归新盘（2026-11-08 用户定）：本次核实（以 REW 详情页为准）能确立该房是开发商新盘/预售的，直接 status=“新盘”、rating 空、viewed=false（与新增一样不能直接打分）。证据任一成立即可：①该房是卡上已有“新盘”房的同项目其他单位（同门牌地址/同开发项目）；②REW 详情页自带新盘证据——如 Property Condition 写 Under Construction、建成/交房年份为未来年份、或页面明示为开发商首卖的新项目。builder 仍按步骤 3 的 builder 口径填（页面明写开发商才填）；查不到开发商不妨碍归新盘，builder 留空即可（2026-11-08 Clermont 两套先例）。下面三条排除规则（年代 / 2房 / 多拼）优先于本条：命中排除规则的按排除入卡，不进新盘。汇报时新盘入卡的必须写明归类证据。
   - 建筑年代已核实为门槛前：直接 status=“排除”、rating=1、note 注明“建筑年代太远（XXXX年）”。门槛按类型分（2026-11-05 用户定）：Townhouse 为 2015 年（2015 年前排除，exclusionReason=“早于2015”，沿 2026-11-04 定案）；双拼 / 独栋为 2000 年（2000 年前排除，exclusionReason=“2000年前”；双拼/独栋 2000 年及以后不因年代排除）。
   - 房数（beds）已核实为 2 或以下：直接 status=“排除”、rating=1、exclusionReason=“2房”（2026-11-01 用户定，与年代、多拼同等待遇）。
   - 明显是多拼/多户（挂牌文案或单元结构表明超过 2 户；独栋挂牌若实为多套间/多户住宅也按此处理）：直接 status=“排除”、rating=1，note 注明“多拼”（及核实依据）。
   - 单元数核实不了是否真双拼：仍进“新增”，note 注明“单元数未核实”。
   - 核实不到 REW 现挂牌（只有镜像、字段对不齐）的：不要入卡，记为未核实，汇报里列出，明天再核。
5. 写入安全：改动前校验 JSON 有效；新 id 接现有最大 id 往后排，sortOrder 同步递增；改动后在 VPS 上用 python json 校验 houses.json 并用 systemctl status rating-card 确认服务仍在运行（不要用无登录 curl 调 /api/houses 验证，那会返回 401，那是密码登录在正常工作，不是故障）。如 SSH 不通、VPS IP 已变、或 houses.json 校验失败，停止写入，汇报失败原因，不要用旧数据覆盖，也不要重试覆盖写。
6. 汇报规则：有新入卡时，在本对话汇报清单（每套：id、地址、MLS、价格、类型、建筑年代、入卡分类及理由、来源页），并说明哪些因限流或核实不到而未入卡；完全没有新房时不要打扰用户（在本次运行记录里写“无新房”即可）。

注意：本任务只负责“发现并入卡新房”这一件事；已有房子的价格/状态同步归每日 MLS 同步任务，本任务不改已有房子的任何字段。
